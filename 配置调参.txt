EngineAI Native SDK（T800 功能合并版）配置与调参说明

一、配置入口

1. 模式和配置映射

  assets/config/t800/mode.yaml

- active_mode: sim 使用仿真配置，robot 使用真机配置。
- mode.robot 和 mode.sim 把 param_tag 映射到具体 YAML。
- 本次新增的 pd_stand_x/pd_stand_y、getup2 和五个击打动作配置均已同时加入 robot、sim。
- install.sh 部署时会在远端自动把 active_mode 改为传入的 mode。

2. 状态机、按键和周期

  assets/config/t800/task_motion/default.yaml

- motion：状态名。
- period：Runner 调度周期，单位秒。
- runner.name：注册的 Runner 名称。
- param_tag：该状态使用的参数配置标签。
- key：统一逻辑按键组合，不是某个遥控器驱动中的原始键号。核心库没有 LT/RT 字符串键；输入适配层用不可能同时出现的 CROSS_Y_LEFT+CROSS_Y_RIGHT 作为 LT 标记、CROSS_X_UP+CROSS_X_DOWN 作为 RT 标记，所以 `[CROSS_Y_LEFT, CROSS_Y_RIGHT, A/X/Y]` 对应物理 LT+A/X/Y，`[CROSS_X_UP, CROSS_X_DOWN, CROSS_Y_RIGHT]` 对应物理 RT+十字键右。
- manual_transition：允许人工切换到的状态。
- auto_transition：Runner 正常结束后的目标状态。

普通改按键或状态关系只改此 YAML，不需要改 src。LT/RT 兼容标记属于底层按键标准化，已在 src/runner/input_command_arbiter 的三类输入适配器中统一处理。

pd_stand、pd_stand_x、pd_stand_y 共用 pd_stand_runner，参数分别为：

  pd_stand      assets/config/t800/pd_stand/robot.yaml（robot）或 default.yaml（sim）
  pd_stand_x    assets/config/t800/pd_stand/pose_x.yaml（趴姿）
  pd_stand_y    assets/config/t800/pd_stand/pose_y.yaml（躺姿）

三者均为 25 关节、3 秒 PD 插值；x/y 使用 urkl_exams 分支中的目标姿态和 4.0 rad 初始偏差阈值。x/y 可以互相切换，也可以切回 pd_stand/passive；只有 passive、pd_stand 能切入 x/y，其他状态不提供直接入边。

3. 常驻任务

  assets/config/t800/task_resident/sim.yaml
  assets/config/t800/task_resident/robot.yaml

前者包含仿真收发，后者包含真机硬件和输入适配。此次保留 SDK 原有常驻任务、ROS2 bridge 和硬件接口。

二、四套步态

1. SDK 普通步态 walk

  配置：assets/config/t800/rl_walking_example/default.yaml
  模型：assets/config/t800/rl_walking_example/policy/
  代码：src/runner/rl_walking_example/

该模块保持官方 SDK 版本，没有加入 new 的上半身锁定逻辑。

- policy_file：相对 assets/config/t800 的 MNN 路径。
- active_joint_names：策略动作关节及顺序，必须与训练/导出一致。
- num_observations、num_include_obs_steps：观测维度和历史帧数，不能脱离模型单独修改。
- default_joint_q：动作零点姿势。
- joint_kp、joint_kd：位置刚度和阻尼。增大 kp 会更硬、更紧跟目标，也更容易冲击/振荡；增大 kd 可增加阻尼，但过大会迟钝和发热。
- action_scale：策略输出到关节目标的幅值。增大后动作更大，风险也更高。
- command_scale_pos/neg：前进、横移、转向的正/负最大指令比例。
- enable_remote_command_lpf：是否过滤遥控指令。
- remote_command_cut_off_frequency：越低越平滑但延迟越大；越高响应越快但更容易突变。
- imu_install_bias：IMU 安装角补偿，顺序为 roll、pitch、yaw。
- transition_time：SDK 步态自身的启动过渡时间。
- disable_transition_joints：不参与 SDK 启动过渡的关节。

2. new 普通步态 walk_custom

  配置：assets/config/t800/rl_walking_custom_example/default.yaml
  模型：assets/config/t800/rl_walking_custom_example/policies/
  代码：src/runner/rl_walking_custom_example/

基础参数含义与 walk 相同。new 的上半身锁定和平滑插值仅存在于此 Runner：

- upper_body_lock_enabled：开关上半身锁定。
- upper_body_lock_joint_q：J13～J17 左臂、J18～J22 右臂的 10 个目标角，单位 rad，顺序不能改变。
- upper_body_lock_interpolation_duration：从进入状态时实测关节角平滑过渡到锁定姿势的时长。增大更柔和但到位更慢；设 0 立即到目标。

3. Leo Lab 步态 walk_leo

  配置：assets/config/t800/rl_walking_leolab_example/default.yaml
  模型：上述 YAML 的 policy_file；当前为 2026-09-06-19-30-18:t800_lowcylinders_ankle_stable_1_seed42/boxing_policy.mnn。
  代码：src/runner/rl_walking_leolab_example/

该 Runner 直接使用官方 SDK 环境 `/opt/engineai_robotics_third_party` 中同一套 MNN 头文件和动态库；请在官方开发/交叉编译容器内构建，不要混接系统中的另一版本 MNN。

- policy_recurrent：true 使用带 hidden/cell 的循环策略；false 使用普通 MLP。
- observation_input_name、hidden_input_name、cell_input_name、action_output_name、hidden_output_name、cell_output_name：MNN 张量名，必须与导出模型一致。
- num_one_step_observations、num_observations、num_actions、num_include_obs_steps：模型 ABI；当前循环策略固定为 84 输入、25 输出、1 帧历史。
- host_joint_names 与 joint_names：训练端到 T800 的逐项关节映射。两组数组必须等长、无重复，不能只改其中一组。
- override_action_joint_names：需要强制覆盖的训练端关节；当前为空，策略控制全部 25 个关节。
- remote_command_tactical_front_offset_deg：Leo 训练坐标系到机器人根坐标系的平面旋转补偿，当前 37 度。
- command_scale_pos/neg：[前后、横移、转向]，单位 [m/s、m/s、rad/s]。比例模式下前两项为速度上限；固定模式下为目标速度。第三项及转向处理保持原样。

2026-09-08 平移启停调参（两个 Leo 的根目录 default.yaml 分别设置）：

- remote_command_translation_proportional：walk_leo=true，摇杆幅度调速；terrain=false，保留原固定目标速度。比例模式必须同时开启 slew，否则拒绝进入，避免误配为阶跃输入。
- remote_command_translation_min_speed：walk_leo=0.50 m/s，比例模式持续非零目标的下限；terrain=0，不参与固定目标模式。下限不能大于 command_scale_pos/neg 前两项中的任一值。
- remote_command_translation_slew_enabled：两者均 true，仅限制平移指令变化，不过滤转向。
- remote_command_translation_acceleration：两者均 1.0 m/s²，数值越小启动越慢、短点按越不容易产生有效移动。
- remote_command_translation_deceleration：两者均 2.0 m/s²，数值越大收速越快、越接近原来的突停；越小停车拖尾越长。
- command_scale_pos/neg：walk_leo 均为 [0.8,0.8,1.0]；terrain 正向 [1.0,0.8,1.5]、负向 [0.8,0.8,1.5]，均未改原速度上限。
- enable_remote_command_lpf：保持 false。这是旧的三轴低通，打开会连转向一起改变；本次不要用它代替上述平移加减速限制。

walk_leo 仍只选择前后/横移中一个主轴。激活后，摇杆幅度 u 在 (0.20,1] 内映射为 0.50+(对应上限-0.50)×(u-0.20)/0.80；例如 u=0.6 时目标约 0.65 m/s。幅度 ≤0.20 时比例目标为零；轴选择仍保留 0.12 释放阈值、0.10 换轴裕量和 0.04 秒启动防抖。terrain 的目标仍在松杆后归零，输出再减速到零。换轴先刹停旧轴；反向先刹停，再保持 0.10 秒零指令，之后向反方向加速。

0.50 下限依据本次用户 MuJoCo 实测：0.2 不能走、0.4 勉强、0.5 基本可用，不代表各方向/实机都已验证。它不是每周期输出的硬下限：启停仍从/到零经过低速区间，不会突然跳到 0.50，也没有强制走满一段时间。很短的点按可能尚未加速到有效速度就开始停止，因此目前不能保证任意短点按都能微调，更不能保证稳定跟踪 0.2 m/s；真低速能力需要后续训练与测试。

50 Hz 下默认每周期最多增加 0.02、减少 0.04 m/s；从零加到 0.5/0.8/1.0 约需 0.5/0.8/1.0 秒，另有启动防抖。松杆后从 0.8/1.0 降到零约需 0.4/0.5 秒，这是指令收速时间，不是实物停车距离保证。实机测试需留余量；切 passive 不等待斜坡，输入仲裁确认无有效遥控源后立即清零、不增加收速拖尾。

调参顺序：先验证 0.5～0.8 持续走路，再测松杆停车、短点按和反向。启停仍抖时对照采集的指令曲线再调 acceleration/deceleration；不要直接把速度下限降回已知不能走的 0.2。若需恢复旧版阶跃行为，将 proportional 和 slew_enabled 都设为 false（第三项转向参数不用改）。

本次包含 C++ 和 ROS2 消息变更，需先按《操作.txt》重新编译完整 SDK；只拷 YAML 到旧程序不会启用新功能。之后单独调上述 YAML 时重启 SDK 读取，不是热更新。当前 robot/sim 均使用两个根目录 default.yaml；模型子目录中的 YAML 不是当前直接加载的配置。未包含新字段的旧 profile 默认保持原固定指令行为。

4. Leo Lab 地形步态 walk_leo_terrain

  配置：assets/config/t800/rl_walking_leolab_terrain_example/default.yaml
  模型：上述 YAML 的 policy_file；当前同为 2026-09-06-19-30-18:t800_lowcylinders_ankle_stable_1_seed42/boxing_policy.mnn。
  代码：src/runner/rl_walking_leolab_example/（复用 Leo runner）
  状态：assets/config/t800/task_motion/default.yaml 中的 walk_leo_terrain。

该部署入口用于无感知 LowCylinders 盲走模型，通过 task_motion 的 LB+X（虚拟键盘 Q+U）进入。当前两个 Leo 根配置都指向 LowCylinders-AnkleStable-1，各自保留一份相同模型；本次未换模型、PD、动作尺度、动作零点或推理频率。后续替换模型以实际启用 YAML 的 policy_file 为准，不要只看文件夹名猜任务。

StdTarget 与 StdOffset 使用同一套观测、动作维度、关节映射和 Leo runner，但 default_joint_pos 不同：StdTarget 保留训练中的原始 boxing-guard nominal 动作零点；StdOffset 把标准姿势文件中的上肢和头部作为动作零点，下肢与躯干仍保留 boxing-guard nominal。切换模型时必须同步切换这套动作零点，不能只替换 MNN；更不能把标准姿势 NPZ 的完整 25 维直接覆盖到部署配置。NoArmAMP 只改变训练时 AMP 判别器使用的状态，部署 actor 仍归 StdOffset 配置族。

terrain example 默认启用根目录中的 StdTarget 配置：mode.yaml 中 robot、sim 的 scope 都是 rl_walking_leolab_terrain_example/default。部署 StdOffset 时，将这两处 scope 同步改成 rl_walking_leolab_terrain_example/profiles/std_offset/default；切回 StdTarget 时改回根 default。根配置与 profile 的 policy_file 可以不同，必须分别核对所指模型；scope、动作零点与 MNN 要匹配，并且 robot、sim 不要只改一处。

Leo 与 terrain Leo 共用同一个 runner，因此 entry_transition_enabled、entry_transition_duration、entry_transition_min_duration、entry_transition_max_duration、entry_transition_max_joint_velocity、entry_transition_max_joint_acceleration、entry_transition_reference_pose_weight、entry_transition_source_tracking_error 的含义和行为一致：进入步态时捕获来源状态最后实际下发的命令，并结合切换瞬间的实测关节状态生成短时过渡，减少从动作或其他步态切入时的突变。max_joint_velocity 与 max_joint_acceleration 共同用于估算自适应时长，其中速度还会用于 qd 裁剪；当前 acceleration 不是逐周期硬 qdd 限制。若某个 terrain profile 不包含这些字段，runner 使用代码中的安全默认值；建议实际使用的 profile 显式保留它们并与已验证的 Leo 配置一致。

本次平移处理与 entry_transition 独立：切入/切出时清空遥控斜坡状态，不继承上一次 Leo 的残留速度。摇杆回中切入时，策略从第一周期仍收到零速度，原关节衔接和循环网络初始化不变；不是等过渡结束才启动策略。若带着非零摇杆切入，新的速度指令会从零加速，这会改变策略响应，不能保证动态恢复能力完全不变。仍需验证起身、击打动作结束及其他步态切入后的稳定性；本次没有新增姿态保护或改变动作切换许可。

2. HoST 起身 getup

  配置：assets/config/t800/rl_getup_example/default.yaml
  模型：assets/config/t800/rl_getup_example/policies/policy.mnn
  模型记录：assets/config/t800/rl_getup_example/policies/policy_manifest.json
  代码：src/runner/rl_getup_example/

- 当前模型 ABI 固定为单帧 76、6 帧历史、总输入 456、输出 23；这些维度和 first_frame_history_mode 不可随意改。
- host_joint_names/joint_names：HoST 到 T800 的关节映射。
- default_joint_pos：为模型契约记录保留，当前 Runner 不用它生成目标。
- joint_stiffness/joint_damping：起身 PD 参数，当前数值明显高于步态；降低可减小冲击但可能没有足够支撑力，必须小幅调整并重新验证。
- action_rescale：全局动作幅值；最终增量为 raw_action × action_rescale × action_scale。增大时动作更强、更危险。
- clamp_joint_targets：true 时把目标限制在机器人关节上下限内，应保持开启。
- entry_max_upright_projected_gravity_z：机器人已经接近直立时拒绝进入该起身。直立时 projected_gravity.z 约为 -1；数值调得更大（如 -0.7）会更严格地拒绝半直立姿势。
- entry_max_angular_velocity_norm：进入起身允许的最大机身角速度。
- success_upright_projected_gravity_z：完成所需的直立阈值；越接近 -1 越严格。
- success_max_angular_velocity_norm：完成所需的稳定阈值；越小越严格。
- success_hold_duration：直立且稳定条件连续保持多久才判定完成。
- timeout_duration：最长执行时间。超时后不会自动进入步态，只允许切 passive 或 pd_stand。

共用代码：

  src/runner/rl_dance_example/

各动作配置：

  dance            assets/config/t800/rl_dance_example/default.yaml
  victory          assets/config/t800/rl_victory_example/default.yaml

- policy_file：动作追踪 MNN 模型。
- trajectory_file_npz：参考动作轨迹。
- joint_names：25 个动作关节及顺序，必须和模型、轨迹一致。
- joint_stiffness/joint_damping：动作 PD 参数。
- action_scale：策略残差幅值。
- resident_control=true：目标为参考轨迹角度 + 策略残差；false：目标为 default_joint_pos + 策略输出。
- lower_body_startup_interpolation_duration：下半身从当前姿势到轨迹起点的过渡时间。
- upper_body_startup_interpolation_duration：下半身启动过渡结束后，上半身到参考轨迹目标帧的过渡时间。
- lower_body_policy_blend_duration：开始策略后，下半身从轨迹起点到策略命令的混合时间。
- trajectory_body_index：body_quat_w 为 N×B×4 时选择第几个 body；当前 T800 轨迹统一取 0。若 body_quat_w 已是 N×4，该值必须为 0。
- trajectory_end_behavior：exit 表示轨迹结束后触发状态机自动切换；hold 表示保持末帧，需人工切换。本工程 dance、victory 和五个击打动作共 7 个动作轨迹使用 exit，正常完成后回 walk_leo；stance_to_supine 仍按任务图自动回 passive。

替换动作模型或轨迹时，可以保持文件名覆盖，也可以把新文件放入对应目录后修改 YAML 路径。NPZ 至少需要 float32、C-order 的 joint_pos、joint_vel、body_quat_w；前两项 Runner 视图必须为 N×25，四元数 Runner 视图必须为 N×4，帧数 N 一致且四元数必须归一化。Runner 只读取这三个键，body_pos_w、body_lin_vel_w、body_ang_vel_w、fps、body_names、schema 和 derived_* 等扩展键会被忽略，不影响策略执行，也不必为了适配当前 Runner 删除。Runner 进入状态时会检查这些条件，并用全零观测做一次模型输出维度/有限值校验。模型输入、输出、观测顺序、关节顺序和轨迹采样频率必须与 Runner 配置一致。

五、T800 机器人资源

最终统一采用 SDK 资源：

  assets/config/t800/model/default.yaml
  assets/resource/t800.xml
  assets/resource/robot/t800/

两仓库的 T800 URDF、mesh、texture、J00～J24 关节顺序和执行器绑定一致。SDK 的 serial_t800.xml 额外显式使用 MuJoCo integrator="implicitfast"，旧工程未指定并依赖默认积分器。因此不要把旧工程的 T800 XML 覆盖到 SDK。

更换资源时，URDF、MJCF、mesh、执行器绑定和 model/default.yaml 必须作为同一版本整体更换；不能只替换 XML 或只改关节名字。策略配置中的 joint_names 也必须同步核对。

六、MuJoCo 吊绳参数

吊绳当前为代码常量，位置在：

  simulation/mujoco/main.cc

- kElasticBandStiffness：弹簧刚度，增大后支撑更强，也更容易引入高频振荡。
- kElasticBandDamping：沿吊绳方向的阻尼，增大可抑制摆动，过大会让运动发黏。
- kElasticBandShoulderAnchors：T800 左右肩部吊点的世界坐标，默认 `[0, 0.20, 3]` 和 `[0, -0.20, 3]`。
- kElasticBandFallbackAnchor：找不到双肩部 body 时的单点回退挂点 `[0, 0, 3]`。
- kElasticBandInitialRestLength：初始自然长度。
- kElasticBandShoulderBodyCandidates：优先查找 `LINK_SHOULDER_PITCH_L/R`，两者同时存在时双肩部同时受力。
- kElasticBandBodyCandidates：双肩部不可用时按顺序查找单点回退 body。

当前 T800 资源没有单独命名的“后背把手/肩部吊环” site，双肩吊挂使用左右 `LINK_SHOULDER_PITCH_L/R` 的 body 原点作为肩部吊环近似挂接点；非 T800 模型或缺少任一肩部 body 时回退到腰部候选 body。双点模式会平分总刚度和阻尼，不会把支撑力翻倍。

模型加载成功后吊绳默认开启。运行时 7/方向上每次缩短 0.1 m，8/方向下每次加长 0.1 m，9 切换开关。

七、修改后是否需要重新编译

- 只改 YAML、MNN、NPY/NPZ/CSV 或机器人资源：不需要重新编译 C++，但要重启程序；真机还需重新部署/同步 assets。
- 改 src、simulation 或参数类头文件：需要重新编译。
- 新增 Runner 目录且带 CMakeLists.txt：官方构建会自动发现，仍执行 ./build.sh；不增加新的构建指令。
- 默认全量构建会包含全部迁移功能。若自行设置 ENGINEAI_ROBOTICS_USED_RUNNERS 并选中 walk_custom、walk_leo、getup/getup2 中任一 T800 专属 Runner，CMake 会从 task_motion/default.yaml、task_resident/robot.yaml、task_resident/sim.yaml 自动提取完整 T800 Runner 集并检查选择列表；缺少 SDK walk、SDK 起身/倒地、基础状态或 robot/sim 常驻 Runner 中任一项都会拒绝配置。仅选择其他机型 Runner 时不触发这项 T800 检查。
- aarch64 与 x86_64 使用同一套源码和配置，但必须部署与机载 CPU 架构相符的 build/<arch>/_install。
