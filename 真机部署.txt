# T800 Native SDK 真机部署

适用分支：`feature/motion_transition`

## 1. 目标板与部署结论

T800 开发版有两块机载电脑：

| 设备 | SSH 地址 | 实测架构 | 实测内核 | 用途 |
| --- | --- | --- | --- | --- |
| Nezha（Robot PC） | `user@192.168.0.163` | `aarch64` | `6.1.141-4-engineai` | Native SDK / 运控策略 |
| NVIDIA Jetson AGX Orin 64GB（AI PC） | `ubuntu@192.168.0.162` | `aarch64` | `5.15.148-6-engine-tegra` | AI 计算 |

Native SDK 的 `src_executor` 真机流程部署到 Nezha，不部署到 Orin。两块板都是 `aarch64`，不能只用 `uname -m` 区分；`install.sh` 会检查架构，并对 T800 拒绝 Jetson/Orin 的内核或设备树特征。


## 2. 编译与下发

在开发电脑仓库根目录执行：

```bash
cd /home/xjh/workspace/zq/engineai_robotics_native_sdk
git switch feature/motion_transition

# 在宿主机执行；build.sh 会自动启动 aarch64 交叉编译环境
./build.sh -a aarch64 -r humble -t release

# 默认下发到 Nezha 的 ~/projects/engineai_robotics
./install.sh t800 robot aarch64
```

如更换网线地址，只修改 `install.sh` 顶部的 `remote_user`、`remote_host`、`remote_dir`。不要把 `remote_dir` 设置为源码目录或用户主目录。安装脚本会把远端 `mode.yaml` 的 `active_mode` 改为 `robot`，并记录本次提交信息。

## 3. 真机启动

当前 Nezha 上已有 `robotics.service` 运行 Native/运控程序。启动本仓库版本前，先停止该服务，避免两个程序同时访问电机：

```bash
ssh user@192.168.0.163
sudo systemctl stop robotics.service
# 确认服务已停止
systemctl is-active robotics.service
# 应输出：inactive
cd ~/projects/engineai_robotics
sudo ./run_robot.sh t800
```

稳定后c掉前台后台运行
nohup sudo ./run_robot.sh pm01_edu > nohup.out 2>&1 &
tail -f nohup.out

## 4. 结束运行并恢复

# 查找进程
pgrep -af "run_robot|src_executor"

#确认进程（看输出路径是否正确）
ps -p <PID> -o pid,ppid,cmd

sudo kill <run_robot的PID>

# 确认已退出
pgrep -af "run_robot|src_executor"
# 无输出 = 已停止

# 如果还在，强制结束
sudo kill -9 <剩余PID>

恢复
sudo systemctl start robotics.service
```
