EngineAI Native SDK（T800 功能合并版）操作说明

一、适用范围

- 仅说明 T800；本次未修改 pm01_edu、t800pro 的状态配置。
- 机器人模型、URDF、MuJoCo XML、mesh 和关节映射统一使用本 SDK 仓库的 T800 资源，不混用 engineai_robotics_new 的机器人 XML。
- 新增 Runner 会被 src/runner/CMakeLists.txt 自动发现，构建和运行命令仍与官方 SDK 相同，不需要额外的功能注册命令。

二、构建与运行命令

启用 GPU 直通将 docker/generate.sh 中的 NVIDIA_GPU_AVAILABLE 改为 y


开发容器：

  ./docker/generate.sh
  engineai_robotics_env

x86_64 编译：

  ./build.sh

aarch64 交叉编译（在宿主机执行，需要 Docker）：

  ./build.sh -a aarch64

产物目录分别为：

  build/x86_64/_install
  build/aarch64/_install

MuJoCo 编译和运行：

  ./scripts/build_mujoco.sh
  ./scripts/run_mujoco.sh t800

仿真时还需在同一容器的另一个终端运行 `./run.sh t800`：run_mujoco.sh 负责 MuJoCo/LCM，run.sh 负责 executor、状态机、遥控输入和策略 Runner。assets/config/t800/mode.yaml 的 active_mode 应为 sim。吊绳默认开启；MuJoCo 窗口中按 7 或方向键上缩短吊绳，按 8 或方向键下加长吊绳，按 9 开关吊绳。

本机运行 SDK：

  ./run.sh t800

虚拟遥控器：

  python3 tools/virtual_gamepad/virtual_gamepad.py

真机部署前，在 install.sh 顶部设置 remote_user、remote_host、remote_dir。部署命令：

  ./install.sh t800 robot aarch64

T800 Native SDK 的真机控制程序部署到 Nezha（Robot PC）`user@192.168.0.163`。当前 Nezha 和 Orin 实际都为 aarch64，不能仅靠架构区分，目标板和网络地址确认方法见 `真机部署.txt`。

机器人端运行：

  sudo ./run_robot.sh t800

install.sh 会把远端 assets/config/t800/mode.yaml 的 active_mode 改为 robot。

三、T800 状态和按键

YAML 中使用的是统一逻辑键。CROSS_X_UP/DOWN 表示十字键上/下，CROSS_Y_LEFT/RIGHT 表示十字键左/右。
当前核心库没有 LT 字符串键，输入适配层将 LT 按下编码成同时存在的 CROSS_Y_LEFT+CROSS_Y_RIGHT 标记；因此下面写的 LT 仍是实际物理按键。

  LB + RB                 passive（软急停；所有状态均可进入）
  LT + A                  pd_stand
  LT + X                  pd_stand_x（趴姿）
  LT + Y                  pd_stand_y（躺姿）
  LB + B                  walk（SDK 普通步态）
  LB + Y                  walk_custom（new 普通步态，上半身锁定和平滑插值）
  LB + A                  walk_leo（Leo Lab 步态）
  LB + X                  walk_leo_terrain（LowCylinders 地形步态）
  RB + B                  dance（SDK 动作追踪）
  RB + Y                  victory
  RB + 十字键上           rl_left_front_kick_002_complete_heightfall
  RB + 十字键下           rl_roundhouse_kick
  RB + 十字键左           rl_straight_punch_L_improved
  RB + 十字键右           rl_left_hook_001_improved
  START + 十字键上        supine_to_stance（SDK 起身）
  LB + START              getup（HoST 起身）
  LB + Back               getup2（HoST 起身第二版本）
  START + 十字键下        stance_to_supine（SDK 主动倒地）

idle 是上电初始/故障恢复状态，不再占用 LB+START；程序进入 idle 后会自动转 passive。

四套步态的摇杆控制相同：左摇杆前后控制前后速度，左摇杆左右控制横向速度，右摇杆左右控制转向角速度。walk_leo_terrain 使用 LowCylinders-MN-StdTarget-Plus 或 LowCylinders-MN-StdOffset-Target-Plus 模型，面向无感知的盲走地形测试。

四、状态切换关系

按键只在当前状态允许目标状态时生效。状态关系如下：

- idle：可切 passive；进入后也会自动转 passive。
- passive：可切 idle、pd_stand、pd_stand_x、pd_stand_y、supine_to_stance、getup、getup2。
- pd_stand：可切 passive、四套步态、全部追踪动作、SDK 起身、HoST 起身以及 pd_stand_x/pd_stand_y。
- pd_stand_x/pd_stand_y：两者可互切，也可切 passive、pd_stand、四套步态、全部追踪动作、SDK 起身和两套 HoST 起身；只有 passive 或 pd_stand 能切入这两个状态，其他状态不能直接切入。
- walk（SDK）：可切 passive、pd_stand、walk_custom、walk_leo、walk_leo_terrain、getup、getup2、主动倒地和全部追踪动作。
- walk_custom：可切 passive、pd_stand、walk、walk_leo、walk_leo_terrain、getup、getup2、主动倒地和全部追踪动作。
- walk_leo：可切 passive、pd_stand、walk、walk_custom、walk_leo_terrain、getup、getup2、主动倒地和全部追踪动作。
- walk_leo_terrain：可切 passive、pd_stand、walk、walk_custom、walk_leo、getup、getup2、主动倒地和全部追踪动作。它与 walk_leo 共用 Leo runner 的 entry_transition，因此从动作或其他步态进入时会执行同样的当前无缝衔接逻辑。
- dance、victory、四个新击打动作：执行中可切 passive、pd_stand 或任一步态；轨迹正常结束后自动回 walk_leo。这里的 walk_leo 是静态默认回落目标；如需动作结束后进入 terrain 步态，可在完成动作后人工按 LB+X 切换。
- supine_to_stance（SDK 起身）：执行中只允许人工切 passive 或 pd_stand；正常完成后自动回 walk_leo。
- getup/getup2（HoST 起身）：可由 walk、walk_custom、walk_leo、walk_leo_terrain 切入；进入时仍执行安全检查，已基本直立（投影重力 z ≤ -0.8）或角速度范数 > 6.0 时会拒绝进入。当投影重力 z ≤ -0.9 且角速度范数 ≤ 2.0 连续保持 0.3 秒后，判定起身成功并自动切入 walk_leo。人工切换时，随时都可以切入四套步态，不受起身成功与否限制。若 8 秒超时仍未满足站稳条件，会停止推进策略、保持最后一帧有效目标并自动切入 passive。
- stance_to_supine（主动倒地）：可切 passive 或 pd_stand；完成后自动回 passive。
- 所有状态均保留 LB + RB 到 passive 的软急停路径。

pd_stand 在本工程中是固定姿势入口，不假设机器人已经站立。因此机器人躺平时也可以先进入 pd_stand，再选择两套起身中的任意一套。

五、遥控器兼容性

RC02、Logitech F710/F310（Xbox/XInput 键位模式）和虚拟遥控器都会转换成同一套 GamepadInfo，以上状态键位对三类输入源共用。LT/L2 的模拟量达到 0.5 以上才视为 LT 按下。

逻辑键与实体键：

  逻辑键             F710/Xbox 式键位       RC02
  LB                 LB                    L1
  RB                 RB                    R1
  LT                 LT                  L2（模拟量 ≥ 0.5）
  A/B/X/Y            A/B/X/Y               A/B/X/Y
  START              Start                 START
  CROSS_X_UP/DOWN    十字键上/下           CROSS_UP/DOWN
  CROSS_Y_LEFT/RIGHT 十字键左/右           CROSS_LEFT/RIGHT

虚拟遥控器键盘：

  LB=Q，RB=E，A=J，B=K，X=U，Y=I，BACK=F1，START=F2，十字键上=W、下=S、左=A、右=D。LT 在虚拟遥控器中使用 LT 滑块调到 0.5 以上；四套步态组合依次为 Q+K、Q+I、Q+J、Q+U，getup/getup2 为 Q+F2、Q+F1。

注意：源码明确适配的是 F710/F310，并固定读取 /dev/input/js0；应使用驱动注释所述的非黄灯 Mode，黄灯 Mode 会交换十字键与左摇杆。普通 Xbox 手柄只有在 Linux joystick 事件编号与该布局一致时才可直接使用，不能仅凭外观为 Xbox 布局就保证兼容。项目逻辑轴把 X 定义为前后、Y 定义为左右，因此 F710 驱动中会把 Linux 物理轴转换到这套命名。RC02 使用 /dev/ttyJS。启动或实体输入掉线后重新选源时按 RC02、F710 的顺序尝试；实体源一旦锁定且在线，不会被后来接入的另一实体源动态抢占。虚拟遥控器激活后作为 override 输入覆盖当前实体输入。
六、安全数据采集（只读） 先启动这个再启动run_t800

采集脚本只订阅 ROS2/LCM 状态，不发布任何关节命令，也不会改变机器人当前状态。建议在启动机器人后、执行动作前先启动采集；不要为了测试而故意绕过硬件保护或撞击机械限位。

在开发容器中启动：

  docker exec -it engineai_robotics_env bash
  cd /home/xjh/workspace/zq/engineai_robotics_native_sdk
  source /opt/ros/humble/setup.bash
  source build/x86_64/ros2_env/install/setup.bash
  python3 tools/safety_monitor/record_safety.py --config assets/config/t800/mode.yaml

也可以指定实验时长和输出目录：

  python3 tools/safety_monitor/record_safety.py --duration 60 --output safety_logs/t800_getup_YYYYMMDD_HHMMSS

采集输出目录包含：

  metadata.json   分支、commit、模型 YAML、URDF、关节顺序、限值和采集参数
  samples.jsonl   以 joint_state 到达为基准的原始状态、命令、诊断、动作状态和 imu_info（四元数、RPY、线加速度、角速度及姿态指标）
  events.jsonl    动作切换、模型限位/速度/力矩越界、电机错误、掉线、禁用和电源错误；限位事件包含 measured_*、target_*，并在 peak 中保留最大越界时的对应值

默认动作状态同时尝试 /motion/motion_state 和 LCM task_state；当前版本若 ROS2 动作状态未发布，优先看 events.jsonl 中 source=lcm 的记录。model_position_limit_violation 表示实测值超出 URDF 模型限值，不等价于硬件已经触发限位；motor_error_code 保留驱动原始错误码，需要结合硬件错误码表判断具体保护原因。

默认只记录限位附近 0.02 rad 的事件。事件中的 target_source=joint_command_feedback、target_stage=post_runner_processing 表示最终下发的关节目标（可能已经经过策略运行器裁剪或动作衔接），不是 MNN 原始 action 或裁剪前 q_des；当前脚本不直接采集后两者。若需要记录命令与实测位置差异，可额外加 --tracking-error-threshold 0.75；该指标在 passive 或动作衔接期间可能是正常现象，应和动作状态、错误码一起分析。

walk、walk_custom、walk_leo、walk_leo_terrain 的关节限位/速度/力矩事件会额外写入 posture_context：posture_class（upright、tilted、fallen_suspected、unknown）、倾角、角速度和加速度异常标志，以及事件发生时的 IMU 原始值。默认阈值为倾斜 35°、疑似倒地 60°、角速度 6 rad/s、加速度偏离 1g 3 m/s²，IMU 数据超过 20 ms 会标记 fresh=false，可用 --imu-max-age-ms、--posture-* 参数调整。

当前接口没有可直接订阅的足端接触测量，因此 posture_context 中 foot_contact 固定为 not_recorded；角速度和加速度只能辅助判断“倒地/冲击/剧烈运动”，不能单独证明脚离地。若要确认脚离地，后续还需要接入足端力传感器、接触开关或经过验证的足端接触估计。
