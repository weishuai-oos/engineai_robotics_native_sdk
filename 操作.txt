EngineAI Native SDK（T800）操作说明

一、环境与编译

下面仿真命令在 SDK 容器的仓库根目录执行。首次创建容器见 README_CN.md 的“容器环境”；已有容器从宿主机进入：

  engineai_robotics_env
  cd /home/xjh/workspace/zq/engineai_robotics_native_sdk

其他电脑将路径改为本机仓库路径。确认 assets/config/t800/mode.yaml 中 active_mode: sim。
首次使用或修改 C++ 后，在容器内编译；已有最新构建可跳过：

  ./build.sh
  ./scripts/build_mujoco.sh

虚拟手柄缺少依赖时，在容器内执行：

  python3 -m pip install -r tools/virtual_gamepad/requirements.txt

如果提示找不到 lcmConfig.cmake，先确认已进入 SDK 容器。中文显示为方块时参考 tools/virtual_gamepad/README.md 的 Chinese font setup。

二、单机仿真（任选一种）

  # 一个实体手柄
  ./scripts/run_single.sh --gamepad /dev/input/js0

  # 一个虚拟手柄
  ./scripts/run_single.sh --virtual-gamepad

单机默认有吊绳辅助；测试自由站立或抗击打时，在 MuJoCo 窗口按数字键 9 关闭，控制台显示 Elastic band disabled。

三、双机仿真（任选一种）

  # 两个实体手柄
  ./scripts/run_duel.sh --gamepad-a /dev/input/js0 --gamepad-b /dev/input/js1

  # A 为虚拟手柄，B 为实体手柄
  ./scripts/run_duel.sh --virtual-gamepad --gamepad-b /dev/input/js0

  # A、B 各一个虚拟手柄
  ./scripts/run_duel.sh --virtual-gamepads

双机默认无吊绳；双虚拟手柄分别控制 A、B，编号策略测试只在 A 启用。

四、开始控制与退出

1. 虚拟手柄先勾选 Enable 或按 F5；双虚拟窗口分别启用。
2. 按 LT+A 进入 PD 准备。双机窗口默认暂停：双方进入 PD 后释放按键，在 MuJoCo 窗口按空格开始物理仿真。
3. 等机器人站稳后，按 LB+A 进入 CombinedV2 走路，使用摇杆控制前后、左右和转向。动作切换应在物理仿真运行时进行。
4. 测试页从 PD 或走路状态点击编号动作，完成后自动回 LB+A 走路；下一项需要手动点击。
5. 关闭仿真或虚拟手柄窗口，或在启动终端按 Ctrl+C，结束本次入口启动的全部进程。切换单机、双机前先正常退出上一会话。

五、常用按键

  LB + RB                 passive（阻尼）
  LT + A / X / Y          pd_stand / pd_stand_x / pd_stand_y
  LB + B                  walk（SDK 普通步态）
  LB + Y                  walk_impact（ImpactV2，154500 轮）
  LB + A                  walk_leo（CombinedV2，140000 轮）
  LB + X                  walk_leo_terrain（地形步态）
  LT + B                  leo_taunt（走路嘲讽，只能从 LB+A 进入）

  RB + B                  SuperMimic 嘲讽，36000 轮
  RB + Y                  SuperMimic 左勾拳，82000 轮
  RB + X                  SuperMimic 拉锤，182000 轮
  RB + A                  SuperMimic 右高踢腿，90000 轮

  RB + 十字键上           01 左勾拳，第二批 26000 轮
  RB + 十字键下           03 左直拳，第六批 12000 轮
  RB + 十字键左           04 左抖拳中，第六批 8000 轮
  RT + 十字键右           02 拉锤，第三批 56000 轮
  RB + 十字键右           05 拉锤，第六批 22000 轮

  START + 十字键上        仰卧起身 supine_to_stance
  START + 十字键右        俯卧起身 prone_to_stance
  LB + START              getup（HoST 起身）
  LB + BACK               getup2（HoST 起身第二版本）
  START + 十字键下        stance_to_supine（主动躺下）

上述 01～05 的实体按键和虚拟手柄测试页共用 assets/config/t800/numbered_actions/ 中的同一份策略。五个旧动作已放入 assets/config/t800/old/上次比赛/；编号清单保留，测试页仍可使用。新增的五个正式动作使用 SuperMimic runner，可从三种 PD 或四种走路进入；完成后自动回 LB+A。其额外 hold_seconds 为 0，并跳过参考轨迹附加的 100 帧静态尾段。

按键仅在当前状态允许目标状态时生效；动作和状态关系以 assets/config/t800/task_motion/default.yaml 为准，策略目录由 mode.yaml 选择。仰卧、俯卧起身可从 passive 或三种 PD 姿态进入：两者都先 PD 过渡到参考首姿态，过渡结束后关节最大误差不超过 0.80 rad 连续 5 个 0.02 秒周期，才启动起身策略；当前不检查姿态、角速度或接触，也不设置等待超时。参考结束后直接交给 LB+A 走路，不另做站稳判定。状态分类与完整衔接见 docs/t800_runner_classification_and_transitions.md。

虚拟手柄键盘：LB=Q、RB=E、A=J、B=K、X=U、Y=I、BACK=F1、START=F2、十字键上=W/下=S/左=A/右=D；LT/RT 使用界面滑块。方向键控制前后左右，N/M 控制左转/右转。修改 YAML 后重新启动会话。

六、如果出现 LCM self test failed

在宿主机检查路由。109 的本机仿真若受 VPN/PPP 路由影响，执行：

  ip route get 239.255.76.67
  sudo ip route replace 239.255.76.67/32 dev lo

该路由通常在容器重启后保留，宿主机重启后需重新设置。使用同一组播地址进行跨电脑或实机通信前，在宿主机撤销：

  sudo ip route del 239.255.76.67/32 dev lo

七、真机与数据采集

真机为一台 T800 使用实体遥控器；交叉编译、部署到 Nezha 和机器人端启动过程见仓库根目录的《真机部署.txt》。部署脚本会将远端 active_mode 设置为 robot。实机的新步态和新动作与旧版已跑通的策略不同，稳定性需分别验证。

需要只读记录 ROS2/LCM 状态时，可在开发容器中先加载 ROS 环境，再执行：

  source /opt/ros/humble/setup.bash
  source build/x86_64/ros2_env/install/setup.bash
  python3 tools/safety_monitor/record_safety.py --config assets/config/t800/mode.yaml

详细数据字段与参数可通过 python3 tools/safety_monitor/record_safety.py --help 查看。

## 模型导出与替换（AnkleCombinedV2）

当前 `LB+A` 已使用最终 **`ckpt_140000.pt`** 导出的模型，日常启动无需导出。以下仅用于重新导出这一个 checkpoint，在**本机训练环境**执行，先退出正在使用该模型的 SDK。路径按实际环境修改：

```bash
(
set -e
LEO_DIR=/srv/shared/home/xjh/workspace/zq_leo_final
SDK_DIR=/srv/shared/home/xjh/workspace/zq/engineai_robotics_native_sdk
LEO_PY=/srv/shared/home/xjh/app/miniconda3/envs/leo/bin/python
MNN_PY=/srv/shared/home/xjh/app/miniconda3/envs/whole_body_tracking/bin/python
CKPT_PATH="$LEO_DIR/logs/cusrl/T800_base-AnkleCombinedV2/2026-11-07-23-48-06:T800_base-AnkleCombinedV2_finetune_2gpu_seed42/ckpt/ckpt_140000.pt"
DEPLOY_DIR="$SDK_DIR/assets/config/t800/rl_walking_leolab_ankle_combined_v2_140000/policies"
OUT_DIR=$(mktemp -d /tmp/engineai-ankle-v2.XXXXXX)
trap 'rm -rf -- "$OUT_DIR"' EXIT

"$LEO_PY" "$LEO_DIR/scripts/cusrl/export_ankle_v2.py" \
  --checkpoint "$CKPT_PATH" --expected-iteration 140000 --output-dir "$OUT_DIR"

"$MNN_PY" -m MNN.tools.mnnconvert \
  -f ONNX --modelFile "$OUT_DIR/actor.onnx" \
  --MNNModel "$OUT_DIR/boxing_policy.mnn" --bizCode MNN --targetVersion 2.9

cp "$OUT_DIR/boxing_policy.mnn" "$DEPLOY_DIR/boxing_policy.mnn"
)
```

只把最终 MNN 放入部署目录，ONNX 和导出记录留在临时目录并在结束时自动清理。转换保持 FP32，`--targetVersion 2.9` 对应 SDK 容器的 MNN 2.9 推理库。

`assets/config/t800/mode.yaml` 的 `mode.sim`、`mode.robot` 均应包含以下选择，当前已配置：

```yaml
    - tag: rl_walking_leolab_example
      scope: rl_walking_leolab_ankle_combined_v2_140000/default
```

运行只需该目录的 `default.yaml` 与 `policies/boxing_policy.mnn`；保持四踝 Kd=2.0。接口为 84 维观测、25 维动作及两组 `[2,1,256]` 循环状态。以上命令只更新 `SDK_DIR` 指定的仓库；在 109 测试时，需同步对应 MNN 后重启单机或双机会话。

该导出脚本仅适用于 CombinedV2。`LB+Y` 的 ImpactV2 需要其带头部掩码的专用导出流程。
