EngineAI Native SDK（T800）操作说明

一、环境与编译

下面仿真命令在 SDK 容器的仓库根目录执行。首次创建容器见 README_CN.md 的“容器环境”；已有容器从宿主机进入：

  engineai_robotics_env_1116
  cd /home/ds/robot/11.16/engineai_robotics_native_sdk

其他电脑将路径改为本机仓库路径。确认 assets/config/t800/mode.yaml 中 active_mode: sim。
首次使用或修改 C++ 后，在容器内编译；已有最新构建可跳过：

  ./build.sh
  ./scripts/build_mujoco.sh

虚拟手柄缺少依赖时，在容器内执行：

  python3 -m pip install -r tools/virtual_gamepad/requirements.txt

如果提示找不到 lcmConfig.cmake，先确认已进入 SDK 容器。中文显示为方块时参考 tools/virtual_gamepad/README.md 的 Chinese font setup。

二、单机仿真（任选一种）

  # 一个实体手柄
  ./scripts/run_single.sh --gamepad /dev/input/js0

  # 一个虚拟手柄
  ./scripts/run_single.sh --virtual-gamepad

单机默认有吊绳辅助；测试自由站立或抗击打时，在 MuJoCo 窗口按数字键 9 关闭，控制台显示 Elastic band disabled。

三、双机仿真（任选一种）

  # 两个实体手柄
  ./scripts/run_duel.sh --gamepad-a /dev/input/js0 --gamepad-b /dev/input/js1

  # A 为虚拟手柄，B 为实体手柄
  ./scripts/run_duel.sh --virtual-gamepad --gamepad-b /dev/input/js0

  # A、B 各一个虚拟手柄
  ./scripts/run_duel.sh --virtual-gamepads

双机默认无吊绳；双虚拟手柄分别控制 A、B。当前项目未提供默认编号策略测试清单。

四、开始控制与退出

1. 虚拟手柄先勾选 Enable 或按 F5；双虚拟窗口分别启用。
2. 按 LT+A 进入 PD 准备。双机窗口默认暂停：双方进入 PD 后释放按键，在 MuJoCo 窗口按空格开始物理仿真。
3. 等机器人站稳后，按 LB+A 进入 DR 171000 主走路，使用摇杆控制前后、左右和转向。动作切换应在物理仿真运行时进行。
4. 测试页从 PD 或走路状态点击编号动作，完成后自动回 LB+A 走路；下一项需要手动点击。
5. 关闭仿真或虚拟手柄窗口，或在启动终端按 Ctrl+C，结束本次入口启动的全部进程。切换单机、双机前先正常退出上一会话。

五、常用按键

  LB + RB                 passive（阻尼）
  BACK + START            idle（初始化状态，确认电机实际使能后进入 passive）
  LT + A / X / Y          pd_stand / pd_stand_x / pd_stand_y
  LB + B                  walk（SDK 普通步态）
  LB + A                  walk_leo（ImpactV2 DR，171000 轮，主走路）
  LB + 十字键上           walk_v2_dr_194500（ImpactV2 DR，194500 轮）
  LB + 十字键右           walk_v2_dr_191500（ImpactV2 DR，191500 轮）
  LB + 十字键下           walk_plus_origin_180000（ImpactV2Plus，180000 轮）
  LB + 十字键左           walk_plus_dr_189000（ImpactV2Plus DR，189000 轮）
  LB + Y                  leo_taunt（走路嘲讽，只能从 LB+A 进入）
  START + 十字键左       getup（HoST 起身）
  LB + START              getup2（HoST 起身第二版本）
  LB + BACK               空闲
  START + 十字键上        supine_to_stance（仰卧起身）
  START + 十字键右        prone_to_stance（俯卧起身）
  START + 十字键下        stance_to_supine（主动躺下）

  上述按键覆盖当前 task_motion 的 27 个正式状态；名单二动作映射如下（保留 ds 电脑虚拟遥控器的原动作编号）：

  拳法：
  RB+十字键上            06  左抖拳（高），32000 轮（supermimic_action_06）
  RB+十字键下            09  左勾拳，20000 轮（supermimic_action_09）
  RB+十字键左            11  左手下拉捅锤，18000 轮（supermimic_action_11）
  RB+十字键右            13  左抖拳（中），32000 轮（supermimic_action_13）

  腿法：
  RT+十字键左            16  左低弹踢，26000 轮（supermimic_action_16）
  RT+十字键右            17  左高弹踢，18000 轮（supermimic_action_17）
  RB+B                   14  左正蹬，18000 轮（supermimic_action_14）
  RB+Y                   19  左低鞭，18000 轮（supermimic_action_19）
  RB+X                   20  左中鞭，18000 轮（supermimic_action_20）
  RB+A                   15  前腿侧踩，18000 轮（supermimic_action_15）

  10 个动作均可从三种 PD 姿态或当前六种走路状态进入，完成后自动回到 LB+A 的 walk_leo。
  拳法 06/09/11/13 的进入衔接已缩短为约 0.12 秒（范围 0.08～0.16 秒）；参考尾部早切为 06/09/11/13 跳过 12/8/8/13 帧。腿部动作 14/15/16/17/19/20 目前未改。
  RT+十字键上、RT+十字键下仍未分配。输入编码使用十字键上、下同时置位表示 RT，因此这两个组合无法区分。

  真机启动时 idle 会先同步一次失能反馈，再请求使能；只有 enabled_motor_state 与 motor_debug 的 enable/offline/error 反馈一致且健康时才进入 passive。反馈等待约 2 秒后进入安全故障路径，仿真环境跳过硬件等待。

按键仅在当前状态允许目标状态时生效；动作和状态关系以 assets/config/t800/task_motion/default.yaml 为准，策略目录由 mode.yaml 选择。仰卧、俯卧起身可从 passive 或三种 PD 姿态进入：两者都先 PD 过渡到参考首姿态，过渡结束后关节最大误差不超过 0.80 rad 连续 5 个 0.02 秒周期，才启动起身策略。参考结束后直接交给 LB+A 主走路。HoST 起身进入后达到直立重力投影阈值即请求切入 LB+A，主走路对 getup/getup2 配置为硬接管，残余速度由走路策略接管。状态分类与完整衔接见 docs/t800_runner_classification_and_transitions.md。

虚拟手柄键盘：LB=Q、RB=E、A=J、B=K、X=U、Y=I、BACK=F1、START=F2、十字键上=W/下=S/左=A/右=D；LT/RT 使用界面滑块。方向键控制前后左右，N/M 控制左转/右转。修改 YAML 后重新启动会话。

六、如果出现 LCM self test failed

在宿主机检查路由。109 的本机仿真若受 VPN/PPP 路由影响，执行：

  ip route get 239.255.76.67
  sudo ip route replace 239.255.76.67/32 dev lo

该路由通常在容器重启后保留，宿主机重启后需重新设置。使用同一组播地址进行跨电脑或实机通信前，在宿主机撤销：

  sudo ip route del 239.255.76.67/32 dev lo

七、真机与数据采集

真机为一台 T800 使用实体遥控器；交叉编译、部署到 Nezha 和机器人端启动过程见仓库根目录的《真机部署.txt》。部署脚本会将远端 active_mode 设置为 robot。实机的新步态和新动作与旧版已跑通的策略不同，稳定性需分别验证。

数据采集不和控制程序共用同一个前台终端，按下面顺序操作：

1. **终端 A：先正常启动程序。**

   仿真仍按本文件第二节启动；真机按《真机部署.txt》第三节启动。
   等窗口、控制器和机器人状态都正常后，不要在终端 A 输入采集命令。

2. **终端 B：另开一个终端，在同一个 SDK 仓库中启动采集器。**

   仿真使用原有采集命令：

   ```bash
   ./tools/safety_monitor/start_recording.sh sim_run_01 --config assets/config/t800/mode.yaml
   ```

   真机使用自动配置命令：

   ```bash
   cd /path/to/engineai_robotics_native_sdk
   ./tools/safety_monitor/start_real_recording.sh real_run_01 --duration 300
   ```

   真机使用 `start_real_recording.sh`，它会自动设置真机 ROS2 网络参数并检查话题。
   终端 B 按 Ctrl+C 只会停止采集，
   不会停止终端 A 中的仿真或真机程序。

3. **结束采集后再结束控制程序。**

   数据写入仓库内的 `records/safety_monitor/<run_name>/`，每次采集一行命令即可。

输入源由正常程序启动时决定：仿真启动器会自动使用虚拟手柄或 Xbox/F710；真机启动时使用 RC02。
不要在终端 B 重新启动控制程序。

策略诊断默认按 100 Hz 采样以减少实时开销；如果本次实验需要每个 500 Hz 控制周期的策略快照，
必须在终端 A 启动正常程序前设置 `ENGINEAI_POLICY_DIAGNOSTICS_HZ=500`。终端 B 不需要设置该变量。
MuJoCo 的 `sim_control_diagnostics` 也默认按 100 Hz 发布；如果需要每个控制周期的 nominal/effective 力矩和命令有效性，
在终端 A 启动仿真前同时设置 `ENGINEAI_SIM_CONTROL_DIAGNOSTICS_HZ=500`。采集器终端 B 不需要设置这些变量。

详细数据字段与参数可通过 `./tools/safety_monitor/start_recording.sh --help` 查看。

## 主走路模型部署

当前 `LB+A` 使用原 `LB+十字键右` 的 **ImpactV2 DR 171000** 模型，日常启动无需导出。新增的 DR 194500 和 DR 191500 分别占用 `LB+十字键上` 与 `LB+十字键右`。若重新生成 MNN，应使用对应训练仓库的导出流程，在本机训练环境执行，并先退出正在使用该模型的 SDK。

重新导出时请使用训练仓库中与 ImpactV2 DR 171000 对应的导出命令，将最终 FP32 MNN 覆盖到上述 `policies/boxing_policy.mnn`，然后重启 SDK 会话。

`assets/config/t800/mode.yaml` 的 `mode.sim`、`mode.robot` 均应包含以下选择，当前已配置：

```yaml
    - tag: rl_walking_leolab_example
      scope: rl_walking_leolab_impact_v2_dr_171000/default
```

部署只需该目录的 `default.yaml` 与 `policies/boxing_policy.mnn`。接口为 84 维观测、25 维动作及两组 `[2,1,256]` 循环状态。更新 MNN 后需重启单机或双机会话。

`LB+Y` 现在由 `leo_taunt` 使用，走路嘲讽复用该主模型作为策略基座。当前六种走路状态共用 Leo runner。
